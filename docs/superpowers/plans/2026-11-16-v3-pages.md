# V3 — Autres pages : plan d'exécution

> **Pour les agents :** sous-skill requis : superpowers:executing-plans (exécution « Native »). Cases à cocher (`- [ ]`).

**But :** construire les 14 pages restantes du plan du site (spec § 5), sur la base de l'accueil validé par Léo le 2026-11-16, et les publier.

**Architecture :** composants de page partagés dans `src/components/page/`, une page Astro par adresse, contenu repris de la V2 (`git show main:<page>.html`) et de l'ancien site (coffre, `Modèle v3 de Léo/www.h2o-partner.fr/`). Les pages provisoires de `[...slug].astro` disparaissent au fur et à mesure.

**Spec :** `docs/superpowers/specs/2026-11-16-refonte-v3-design.md` · Plan précédent : `2026-11-16-v3-accueil.md` (contraintes globales identiques).

## Contraintes globales
Mêmes que le plan de l'accueil (palette, polices, aucun fait inventé, « Demander un diagnostic », noindex par défaut, `url()` partout, sans cookie, lisible sans JavaScript et en mouvement réduit). En plus :
- Chaque page : un `h1`, titre ≤ 60 caractères, description de 50 à 160 caractères, fil d'Ariane visible et `BreadcrumbList`, `Service` sur les pages de prestation, liens vers les pages voisines.
- Haut de page sombre (direction B) pour toutes les pages, puis contenu clair ; au moins une grande image par écran.
- Textes nouveaux ajoutés à `docs/textes-a-relire.md`.

## Points de vigilance
1. Formulaires sans clé Web3Forms : le message doit s'ouvrir dans la messagerie (mailto), sans rien perdre ; avec `PUBLIC_WEB3FORMS_KEY`, envoi réel et message de confirmation.
2. Vrai ou faux au clavier : boutons, réponse annoncée (`aria-live`), score.
3. Diagnostic en étapes : retour en arrière sans perte, validation accessible, utilisable sans JavaScript (toutes les étapes visibles).
4. Pages longues sur téléphone 360 px : pas de débordement (tableau CLACK dans un conteneur défilant).
5. Aucun lien interne cassé entre les 17 pages (test `base-path` parcourt tout le site).
